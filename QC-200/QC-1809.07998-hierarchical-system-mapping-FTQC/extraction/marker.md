## Abstract

Considering the large-scale quantum computer, it is important to know how much quantum computational resources is necessary precisely and quickly. Unfortunately the previous methods so far cannot support a large-scale quantum computing practically and therefore the analysis because they usually use a non-structured code. To overcome this problem, we propose a fast mapping by using the hierarchical assembly code which is much more compact than the non-structured code. During the mapping process, the necessary modules and their interconnection can be dynamically mapped by using the communication bus at the cost of additional qubits. In our study, the proposed method works very fast such as 1 hour than 1500 days for Shor algorithm to factorize 512-bit integer. Meanwhile, since the hierarchical assembly code has high degree of locality, it has shorter SWAP chains and hence it does not increase the quantum computation time than expected.

**Index Terms:** system mapping, quantum assembly code, large-scale quantum computing, quantum computer architecture

## 1  Introduction

The era of quantum computing already started. Several gigantic IT corporations have been devoted to develop quantum computing devices, and some of them are now providing quantum computing cloud service to the public. But the scale of the devices are still small (dozens of qubits), and therefore applications for them are also very limited. While we look forward to seeing a quantum supremacy with such a small scale quantum device soon, most of the public have interest in a large scale universal quantum computer that can run large-sized quantum algorithms to solve real world problems.

Suppose that you have a quantum computing hardware and a quantum algorithm. What do you have to do to run the algorithm with the hardware? Quantum algorithm is a logical description of how to solve a given problem. It is usually based on ideal quantum computing hardware with noiseless gate and long qubit interaction. However, in reality, a quantum computer as a physical entity has a certain physical and logical limitation. For example, qubits might be peculiarly arranged and connected with each other. Therefore, to run a quantum algorithm on a quantum computer, we have to prepare an architecture-specific description of a quantum algorithm beforehand. This is why a **quantum system mapping** is necessary.

The principle of a quantum system mapping is straightforward. Initialize a quantum computer architecture and recast a quantum algorithm for the architecture. A detailed procedure completely depends on a quantum algorithm, a quantum computer architecture and a mapping algorithm. An architecture-specific description of a quantum algorithm, the main product of the system mapping, is called a **system code** in this work.

Quantum algorithm for the system mapping is provided in a **quantum assembly code (QASM)** format. QASM is an intermediate representation of a quantum algorithm between an abstract description and a physical machine instruction description. There are two kinds of QASMs in terms of structure: **non-modular** type (naïvely enumerates all quantum instructions) and **modular** type (hierarchically structured with multiple functions called a module).

### Table 1: The QASM size comparison over Shor's factoring algorithm

The QASMs are generated by using the compiler ScaffCC.

| Input Size | Non-Modular | Modular  |
|------------|-------------|----------|
| 128        | 1.7 TB      | 23.5 MB  |
| 256        | 14.2 TB     | 88.1 MB  |
| 512        | 39.0 TB     | 338.6 MB |

We obtained a 39 TB sized non-modular QASM for Shor algorithm to factorize a 512-bit integer. Due to the lack of classical storage and memory, we could not even attempt to generate a non-modular QASM for a larger quantum algorithm.

Suppose that there is an n-qubit composite quantum operation U composed of K quantum gates and it is called as much as N times. To represent such N iterations, a non-modular QASM requires K × N quantum instructions, but a modular QASM only requires K + N instructions by defining U as a module. Empirically, the values of K, N are not small in a non-trivial quantum algorithm.¹

¹ In general, K is O(10²) and N is O(10⁴) ∼ O(10⁶) in Shor algorithm.

## 2  Hierarchical System Mapping

### 2.1  Hierarchically Structured Qubit Layouts

Modules are arranged on a 1D array (with a communication bus between them) and qubits inside each module are arranged on a 2D array. Local qubits are initialized, manipulated and measured within a module; parameter qubits are passed between modules over a communication bus. Dummy qubits (NULL cells) are sometimes required to form the 2D rectangular shape of a module.

Qubits inside a module support universal quantum computing (data qubits + ancilla qubits for QEC + logical operations). Qubits composing the communication bus do not need to support universal quantum computing, in particular logical non-transversal gates.

### 2.2  Mapping Algorithm

System mapping begins with the initialization of a quantum computer architecture (a qubit array). A qubit array is hierarchically structured. Modules and bus are composed of logical qubits encoded by quantum error-correcting codes.

For mapping a module M, a local table is initialized as (time[qᵢ]=0, cycle[qᵢ]=0) over i = 1..n. As mapping proceeds, `time[qᵢ] += waitₜ + uₜ` and `cycle[qᵢ] += wait_c + 1`. On finishing, module performance is recorded on the global table: `time[M] = maxᵢ time[qᵢ]`, `cycle[M] = maxᵢ cycle[qᵢ]`.

**Module call procedure (7 steps, see Fig. 1):**
1. (forward) move qubits to the bus
2. (forward) move to the target module
3. (forward) move to the parameter qubit cells
4. module operations
5. (backward) move qubits to the bus
6. (backward) move to the original module
7. (backward) move to the original qubit positions

Once a module is mapped, its performance is cached; subsequent calls with equivalent argument placements reuse the cached result. This is the key algorithmic reason the modular mapping is orders of magnitude faster.

## 3  Discussion

### Fig. 2: Required mapping time (seconds), hierarchical vs non-modular

| Algorithm    | Non-Modular time | Modular time |
|--------------|------------------|--------------|
| Shor-128     | 1.8 × 10⁶ s      | 1.2 × 10² s  |
| Shor-256     | 1.5 × 10⁷ s      | 5.9 × 10² s  |
| Shor-512     | 1.3 × 10⁸ s (≈1500 days) | 3.3 × 10³ s (≈1 hour) |

The mapping for Shor-512 with a non-modular QASM requires 1500 days, but the proposed mapping can be done within 1 hour. Implementation: Python, on a 3.5 GHz CPU / 128 GB memory system. Non-modular times are estimated from statistics obtained from the proposed mapping.

### Table 2: Quantum resource comparison, Shor algorithm

Qubits column for hierarchical: "computing qubits (bus qubits)". Bandwidth of the bus is taken equal to the maximum number of parameter qubits.

| Algorithm | Non-Modular Qubits | Non-Modular SWAPs | Hierarchical Qubits | Hierarchical SWAPs |
|-----------|--------------------|-------------------|---------------------|--------------------|
| Shor-4    | 46                 | 4.08 × 10⁴        | 115 (374)           | 1.23 × 10⁶         |
| Shor-8    | 90                 | 4.71 × 10⁵        | 227 (1,122)         | 1.02 × 10⁷         |
| Shor-16   | 178                | 5.82 × 10⁶        | 448 (3,055)         | 7.66 × 10⁷         |

**Trade-off:** hierarchical uses ~2.5× more computing qubits + arbitrary bus qubits, and more raw SWAPs. However, only 10% of gates are SWAPs and ~99% of SWAPs happen during qubit passing (parallelizable). Only a half-to-a-third of SWAPs actually contribute to circuit depth. The ratio of hierarchical-to-non-modular SWAPs shrinks with size: 30.3× (Shor-4) → 21.8× (Shor-8) → 13.16× (Shor-16), suggesting the gap vanishes for very large algorithms.

**Within-module CNOT-SWAP overhead** (proposed vs non-modular):
- Shor-4: 0.04 vs 1.00
- Shor-8: 0.02 vs 1.42
- Shor-16: 0.02 vs 2.18
- Shor-128: 0.009 (proposed only)
- Shor-256: 0.007 (proposed only)
- Shor-512: 0.005 (proposed only)

Qubit-placement optimization (linear programming, per Shafaei et al. 2014) is applied. Circuit-depth reduction is <0.01% for Shor (negligible) but 1–6% for BWT algorithm (e.g. 2.42×10⁵ → 2.26×10⁵ for BWT-10).

## 4  Conclusion

Future work: apply a more realistic quantum computer architecture and improve the mapping algorithm. Currently all qubits are assumed to work concurrently; in reality some qubits take longer for error correction or non-transversal logical gates. Communication bus assumed on-demand / on-time — practical network traffic and congestion (especially for highly parallel applications) may disturb this. The current mapping uses many qubits, most of which just wait during most of the execution time. Future work will improve spatial efficiency.
