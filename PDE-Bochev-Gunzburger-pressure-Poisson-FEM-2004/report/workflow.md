# Workflow

## High-level plan (executed)

1. **Fetch paper** — Semantic Scholar API by DOI → open-access PDF from author's FSU page.
2. **Extract text** — `pdftotext -layout` (marker/nougat not installed).
3. **Read + understand** — 20 pages; identify testable claims (Thm 4.1, 4.2, 5.4, 5.5, Lemma 5.2). Observed: no numerical experiments in the paper — must design our own.

6. **Debug** — polynomial-reproduction test caught the V^h vs V^h_0 bug for −Δ_h.
7. **Run experiments** — convergence study (4 meshes × 2 benchmarks) + stability sweep (8 values of δ) + zero-δ control.
8. **Analyze** — verify predicted rates from Thm 5.5; confirm boundedness across δ range from Thm 5.4; confirm polynomial-preservation from Lemma 5.2.
9. **Report** — write REPORT.md, REPORT.tex, brief.md, open_questions.json, failure_analysis.md, artifacts_summary.md.

## Skills / techniques used

- **Finite element method** — Galerkin variational formulation, mixed methods, LBB (inf-sup) condition, stabilized formulations, weak vs strong consistency.
- **scikit-fem API** — `MeshTri.init_tensor`, `ElementVector`, `Basis`, `BilinearForm`, `LinearForm`, `Functional`, `.get_dofs(facets=...)`, `.project()`, `.interpolate()`.
- **Sparse linear algebra** — block matrix construction via `sp.hstack` / `sp.vstack`, factorization via `splu`, Dirichlet BC elimination via row/column masking.
- **Convergence-rate analysis** — log2 successive ratios; expected O(h^r) rate from theory; boundary-layer effects for pre-asymptotic meshes.
- **Consistency debugging** — polynomial-reproduction test for weakly-consistent methods (a classical FE-verification technique: any method that claims to converge with rate ≥ p+1 for smooth solutions must reproduce degree-p polynomials exactly).
