\section{Paper and target}

Ketcheson, D. et al., \emph{NodePy: A package for the analysis of numerical
ODE solvers}, JOSS \textbf{5}(55), 2515 (2020). DOI
\href{https://doi.org/10.21105/joss.02515}{10.21105/joss.02515}.

NodePy is a Python package for symbolic $+$ numerical analysis of numerical
ODE solvers. It represents Runge--Kutta (RK), linear multistep, and
additive/two-step methods as first-class Python objects and exposes:
formal order of accuracy via Butcher-tree order conditions; region of
absolute stability via the stability function
$R(z) = 1 + z\,b^{T}(I - zA)^{-1}\mathbf{1}$; and the SSP
(strong-stability-preserving) coefficient (radius of absolute
monotonicity). It also runs actual IVP integrations to empirically verify
convergence rates. The JOSS paper is a 4-page description of the software
artifact.

\section{Method}

All work performed in \texttt{work/}; evidence written to
\texttt{report/evidence/}.

\begin{enumerate}
  \item \texttt{python3 -m venv work/.venv \&\& source work/.venv/bin/activate}
  \item \texttt{pip install nodepy matplotlib numpy sympy scipy} $\rightarrow$
        \texttt{nodepy 1.0.1} (latest on PyPI).
  \item \textbf{Orders (C1)}: for each name in
        \{RK44, Heun33, SSP22, SSP33, SSP53, SSP104, Merson43, Fehlberg45,
        DP5, CK5, BuRK65\}, called \texttt{m = rk.loadRKM(name); m.order()}
        with \texttt{mode='exact'} fallback.
  \item \textbf{SSP coefficients (C2)}: \texttt{m.absolute\_monotonicity\_radius()}.
  \item \textbf{Stability regions (C3)}:
        \texttt{m.plot\_stability\_region(N=200, bounds=[-10,2,-6,6])} for
        RK44, DP5, SSP104, plus an independent numeric scan of
        $|R(iy)|$ for $y \in [0.5, 3.0]$.
  \item \textbf{Empirical convergence (C4)}: a hand-coded classical RK step
        driven by the extracted Butcher tableau
        (\texttt{A = np.array(m.A, dtype=float)}, same for $b$), applied to
        Dahlquist $y' = -y,\ y(0) = 1$ from $t=0$ to $T=1$ with
        $N \in \{10, 20, 40, 80, 160, 320\}$. Compared to
        $\exp(-1) = 0.367879441171$; observed order estimated by
        $\log_2(\text{err}_N / \text{err}_{2N})$.
  \item \textbf{Verdict}: LLM-judge --- full evidence bundle sent to Argo
        \texttt{argo:claude-opus-4.7} at \texttt{http://localhost:44497/v1}
        (FREE endpoint per project rule), returned strict-JSON verdict.
\end{enumerate}

Tools: \texttt{nodepy==1.0.1}, \texttt{numpy}, \texttt{matplotlib},
\texttt{sympy}, \texttt{scipy}, Python 3.13, macOS 25.3.0.

\section{Verdict}

\textbf{REPLICATED.}

NodePy is a software artifact whose value proposition is ``correctly
compute standard analytical properties of RK methods and let users verify
convergence experimentally.'' Every one of the four headline capabilities
was independently re-executed on a fresh install and produced numbers
matching either theoretical values (integer orders, published SSP
coefficients, known stability limits) or, for the empirical convergence
experiment, matching the formal orders of the methods themselves to two
decimals across five different methods. There were no contradictions and
no capability was inaccessible.

\section{Genuine critique}

The REPLICATED verdict is strong, but the following caveats and scope
limits should be explicit for downstream readers:

\begin{enumerate}

\item \textbf{Scope of the paper is the artifact, not novel scientific
claims.} The JOSS paper introduces NodePy as a software package; there is
no new theorem, no new method, no new experimental result to reproduce.
``REPLICATED'' here means the software still installs and correctly
computes the same standard quantities documented in the RK literature,
not that any new scientific finding was independently confirmed. Readers
should not over-interpret the verdict.

\item \textbf{SSP53 numerical-tolerance edge case.} Default
\texttt{.order()} returned 0 for SSP53 with a NodePy warning
(``Apparent order is 0; this may be due to round-off''). Only after
falling back to \texttt{mode='exact'} did the correct order 3 appear.
This is a real usability bug of the library at its default settings; a
naive first-time user could conclude SSP53 has ``order 0.'' We coded
around it, but it deserves flagging.

\item \textbf{Verified subset is narrow.} Only RK methods were exercised;
NodePy also supports linear multistep, additive, and two-step methods
(and additional analytical machinery like error-constant computation,
internal stability, additive-RK order conditions, dense output, and
adjoint-based analyses). None of that surface was independently
re-executed here. C1--C5 collectively cover the JOSS paper's own examples
but not the full library.

\item \textbf{Empirical convergence uses one benchmark ODE.} The
convergence experiment is entirely on Dahlquist $y' = -y$, a scalar
linear autonomous test problem. Order verification on nonlinear systems,
stiff systems, or systems with structure (Hamiltonian, symplectic) was
not exercised. The observed-order results agree with theory in the easy
regime; that does not certify nontrivial regimes.

\item \textbf{DP5 result hits floating-point epsilon.} At $N \ge 160$ the
DP5 error saturates at $\sim 2.2\text{e-}16$, so the observed-order
estimate becomes $\infty$ / floor-dominated. This is expected and does
not invalidate the match, but the observed order at high $N$ is
uninformative for DP5 and should not be interpreted as ``exceeds order
5.''

\item \textbf{Stability plots verified indirectly.} The PNGs from
NodePy's plotter were spot-checked against an independent numerical scan
of $|R(iy)|$ on the imaginary axis, not against an independent contour
extraction of the whole region. A rendering bug that shifted the
plot only far off the imaginary axis would not be caught.

\item \textbf{Judge is a single LLM at a single temperature.} The verdict
also depends on an Argo Claude Opus 4.7 LLM-judge over the evidence
bundle. That model is capable but is not a second independent human;
readers should weight the machine tables (Tables 4.1--4.4) above the
LLM-judge JSON.

\end{enumerate}

None of these caveats change the verdict. Every headline capability
matches published/theoretical values within rounding. The scope of what
``REPLICATED'' means, however, is: NodePy 1.0.1 still does what its JOSS
paper says it does, on the examples the paper itself highlights, on a
fresh macOS Python 3.13 install.
