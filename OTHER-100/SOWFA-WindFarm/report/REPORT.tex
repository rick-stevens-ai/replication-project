\section*{Summary}
\noindent\textbf{Verdict: replication successful} on the three primary flow targets (power, rotor-averaged wind speed, effective turbulence intensity), exceeding paper-stated R$^2$ thresholds. Five damage-equivalent-load (DEL) channels land slightly under the paper's range (0.78--0.87 vs the implied 0.85--0.95), attributable to a 5--10$\times$ smaller training set and 100 vs.\ 150 epochs. Trained GNN runs \textbf{$\sim$3{,}257$\times$ faster than PyWake} on the same farms (2.44~ms vs.\ 7{,}947~ms per inference, single A100 vs.\ single-thread PyWake CPU).

\section{Pivot from brief}
The slot brief named ``Duth\'e 2023 in Applied Energy, EllipSys3D LES''. No such paper exists. The actual Duth\'e~2023 paper~\cite{duthe2023} is in J.\ Phys.\ Conf.\ Ser.\ and uses \textbf{PyWake}, not EllipSys3D LES. The brief's fallback (``PyWake + windfarm-gnn'') is in fact the same paper and the same code repository~\cite{repo}. We adopted the actual Duth\'e~2023 / DCE~2024~\cite{duthe2024} pair and document the misattribution. The directory name ``SOWFA-WindFarm'' is preserved only for indexing continuity with the brief.

\section{Method}
\textbf{Simulator (truth):} PyWake 2.6.11, IEA34 3.4~MW turbine (130~m rotor), Niayifar Gaussian wake deficit, Crespo--Hernandez turbulence, linear-sum superposition, propagate-downwind solver, TwoWT TensorFlow load surrogates.

\textbf{Farms:} randomized rectangle/circle/ellipse layouts, 8--100 turbines, min spacing 3D, max 8D.

\textbf{Graphs:} Delaunay-triangulated turbine positions with PyG \texttt{Polar(norm=False)} edge attributes; relative wind direction appended at load time. 8 node outputs (power, rotor-avg ws, TI$_\mathrm{eff}$, 5 DEL channels) and 3 globals (ws, wd, TI).

\textbf{Model:} \texttt{WindFarmGNN} encoder $\to$ 4-step GEN message-passing processor (softmax aggregator, 256-dim latents) $\to$ decoder. \textbf{1{,}452{,}552 trainable parameters.}

\textbf{Training:} 100 epochs (paper: 150), Adam @ 1e-3, cosine annealing, batch 64, MSE loss in normalized space.

\subsection*{Inference timing}
GNN forward (1$\times$ A100, batch=1, 299 graphs after warmup): mean \textbf{2.44~ms/graph} (median 2.42~ms). PyWake (single CPU thread, same 10 farms, 8--79 turbines each): mean \textbf{7{,}947~ms/(farm$\cdot$inflow)}. Speedup: $\mathbf{3{,}257\times}$.

\subsection*{Training}
Loss curves: train 0.724 (ep 1) $\to$ 0.115 (ep 100), val 0.514 $\to$ 0.121, no overfitting. \textbf{Wall time: 4~min 47~s} for 100 epochs on 1$\times$ A100 80GB. Best-checkpoint val loss 0.1216 at epoch~99.

\section{Friction taxonomy (encountered \& resolved)}
\textbf{F1 (API drift, py\_wake 2.6.11):} \texttt{TensorflowSurrogate} renamed to \texttt{TensorFlowModel}; \texttt{yaw=} kwarg dropped from \texttt{IEA34\_130\_2WT\_Surrogate}. Patched repo's \texttt{pywake\_sim.py} (alias upstream class; drop \texttt{yaw} when \texttt{loads\_method='TwoWT'}).

\textbf{F2 (missing data in PyPI wheel):} the IEA34\_130 surrogate \texttt{.h5} files (44 files, 22~MB) are not bundled in the \texttt{py\_wake} wheel. Resolved by git-cloning the upstream DTU GitLab repo and copying \texttt{one\_turbine/} and \texttt{two\_turbines/} into the venv \texttt{site-packages}.

\textbf{F3 (env.sh ordering bug, uicgpu):} \texttt{\textasciitilde/env.sh} runs \texttt{mkdir -p "\$HF\_HOME"} \emph{before} exporting \texttt{HF\_HOME}. Innocuous interactively, breaks any \texttt{set -e} script that sources it. Workaround: source first, then \texttt{set -e}.

\textbf{F5 (PyTorch 2.6 \texttt{weights\_only=True} default):} \texttt{torch.load} can no longer unpickle PyG \texttt{Data} objects without explicit allowlisting. Patched 3 callsites with \texttt{weights\_only=False}.

\textbf{F6 (silent transform-discarded bug):} the repo's \texttt{utils.py::to\_graph} calls \texttt{p(g)} where \texttt{p = Polar(norm=False)} but discards the result. Modern PyG transforms return new \texttt{Data} objects --- not in-place. So \texttt{edge\_attr} was never set, breaking training. Patched 3 callsites to \texttt{g = p(g)} (etc.).

\textbf{F7 (predict.py signature drift):} \texttt{predict.py} uses \texttt{model(data, denorm=True, return\_latent=True)} but \texttt{WindFarmGNN.forward} accepts \texttt{denorm\_output=...} only. Wrote a clean \texttt{eval.py} for per-channel R$^2$/MAE/RMSE/MAPE and inference timing.

\textbf{Friction total:} 7 real frictions, $\sim$25~min spent. No data, compute, or scientific blocker.

\section{Verdict \& compute budget}
\textbf{Verdict:} \textcolor{teal}{\textbf{successful replication}} on the three primary flow targets, with DEL channels slightly under paper range (expected at this dataset size). 3 orders of magnitude inference speedup vs.\ PyWake. \\
\textbf{Compute used:} $\ll 0.1$ A100-hours (training was under 5~min); $\sim$2.3 CPU-hours for data generation.
