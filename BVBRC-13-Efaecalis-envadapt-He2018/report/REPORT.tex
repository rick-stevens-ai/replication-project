\begin{abstract}
This report audits a free-tool re-execution of He \emph{et al.} (2018, \emph{BMC Genomics} 19:527, doi:10.1186/s12864-018-4887-3), a comparative genomic study of 78 \emph{Enterococcus faecalis} genomes across six ecological niches. We recomputed every numerical claim directly from the staged TSV/FASTA artifacts in the working directory without trusting any prior self-report. The strain-panel, genome-size/GC, core-genome scaffold, and antibiotic-resistance (AR) gene stages replicate essentially exactly. The paper's biological centerpiece --- Scoary pan-GWAS for 293 niche-specific genes --- was not executed; the ML phylogeny cannot be verified because the Newick file is a corrupt stderr log; virulence-factor (VF) counts are systematically low; the PHASTER prophage stage is absent; and one input genome (Merz96) is almost certainly not \emph{E. faecalis}. \textbf{Verdict: PARTIAL replication (Coverage 6/10, Agreement 7/10).}
\end{abstract}

\section{GENUINE CRITIQUE (mandatory 6/22 reproducibility-blocker review)}
This section is a candid critique of what is actually preventing this replication from being called ``full,'' written without spin. Each blocker names the precise missing artifact needed to close it.

\subsection*{Blocker \#1 --- Corrupt phylogenetic tree}
\texttt{results/phylogeny/core\_tree.nwk} is 939\,B and contains only FastTree's stderr log (version banner, input path, NNI/SPR iteration timings). It has 2 parentheses, 23 commas, and no terminal semicolon --- \emph{it is not a Newick string at all.} Whoever ran FastTree captured stderr instead of stdout. \textbf{Consequence:} paper claim C8 (four branches A/B/C/D with 19/22/16/21 strains) is unverifiable, and every downstream ``niche-across-clade'' argument becomes untestable. \textbf{Precise fix:} rerun \texttt{FastTree -gtr -nt core\_concat\_100.fasta > core\_tree.nwk}. Input MSA is present; runtime is seconds.

\subsection*{Blocker \#2 --- Niche-specific gene analysis missing (the paper's central biological argument)}
The paper's headline biology --- 293 environment-specific genes (143 blood, 66 dairy, 84 water) --- depends on Scoary 1.6.16 pan-GWAS on the presence/absence matrix using niche labels, with BH-corrected $p<0.05$ and 1000 permutations. \emph{None of this is staged.} The presence/absence matrix (13{,}255 $\times$ 78) exists and niche labels exist in \texttt{ar\_summary.tsv}, so the analysis is runnable in this directory but was not executed. \textbf{Precise missing artifact:} \texttt{results/pangwas/scoary\_results.csv} plus the input traits TSV.

\subsection*{Blocker \#3 --- Pan-genome over-fragmentation (13{,}255 vs paper's 10{,}573, +25\%)}
The paper used SiLiX with 80\% identity / 80\% alignment coverage. Our clusters came from CD-HIT at \emph{unknown} thresholds --- \texttt{scripts/} is empty, so the command line is lost. A +25\% cluster inflation is the classic signature of a too-strict identity threshold or a missing length-coverage filter, and it silently propagates into every ``novel/accessory gene'' count. \textbf{Precise fix:} preserve the clustering command line (or a \texttt{run\_pangenome.sh} script), and ideally re-run with SiLiX 80/80 to match the paper, or CD-HIT with \texttt{-c 0.80 -aS 0.80 -aL 0.80} plus a documented reason for the substitution.

\subsection*{Blocker \#4 --- VF undercount, especially V583 (52 vs 34)}
Paper reports 60 unique VFs and V583 = 52; we recover 37 unique and V583 = 34. The paper used VFDB with $E<10^{-15}$ and $\geq 95\%$ identity, pulling from VFDB \emph{setB} (full set including predicted/hypothetical VFs), whereas the database in \texttt{data/databases/} is \texttt{VFDB\_setA\_pro.fas} (curated core only). SetA vs setB systematically explains the shortfall for a well-studied strain like V583 that gains many predicted-VF entries in setB. \textbf{Precise fix:} re-BLAST against \texttt{VFDB\_setB\_pro.fas} at identical thresholds and regenerate the per-strain table, or document the deliberate setA restriction and report VF numbers as a strict lower bound.

\subsection*{Blocker \#5 --- Prophage stage entirely absent}
Paper claim of 116 intact prophages across 65/78 genomes (PHASTER) is not testable. \texttt{data/proteins/} has all 78 proteomes but PHASTER needs nucleotide assemblies, which are not present in the working directory at all (no \texttt{data/genomes/*.fna}). \textbf{Precise missing artifact:} assembled nucleotide FASTAs for all 78 strains plus PHASTER per-genome output --- or a documented free substitute (PHASTEST, Phigaro, or VirSorter2).

\subsection*{Blocker \#6 --- Merz96 is almost certainly not \emph{E. faecalis}}
\texttt{Merz96.faa} corresponds to a genome listed at 5.21\,Mb and 41.2\% GC, both wildly outside the \emph{E. faecalis} envelope (every other strain is 2.67--3.26\,Mb at 36.99--38.03\% GC). This is a mis-fetched or misnamed assembly, likely an \emph{E. faecium} or a contaminated draft. It was nevertheless retained in the AR (Classic\_AR = 16, second-highest) and VF (23) tables and would distort any niche-vs-clade analysis if it ended up in a ``blood'' cluster. The current report excludes it only from the size/GC mean footnote (C3); no other table has been regenerated. \textbf{Precise fix:} replace \texttt{Merz96.faa} with the correct \emph{E. faecalis} Merz96 assembly (verify NCBI accession) or drop the strain and rerun pangenome / core / AR / VF tabulations on N=77.

\section{Verdict}
\textbf{PARTIAL replication.} The scaffold layer of the paper --- \emph{what strains, what sizes, what AR genes, what core-genome shape} --- reproduces cleanly and quantitatively: strain panel, niche counts, genome size and GC, core-AR gene set, mean classic AR per genome, and identity of the most-resistant strains all match He \emph{et al.} 2018 essentially exactly. However:
\begin{itemize}[leftmargin=1.3em, itemsep=1pt]
  \item the paper's biological centerpiece (niche-associated gene discovery, 293 genes) was not attempted;
  \item the headline phylogeny (four clades A/B/C/D) cannot be checked because the Newick file is a corrupt log;
  \item the VF survey systematically under-counts (likely VFDB setA vs setB);
  \item the pan-genome cluster count is $\sim 25\%$ high (likely SiLiX-vs-CD-HIT with unpreserved parameters);
  \item the prophage stage is absent;
  \item one input genome (Merz96) is almost certainly not \emph{E. faecalis}.
\end{itemize}

A focused 1--2 day cleanup would close most blockers: (1)~re-emit the FastTree Newick from the staged concatenated alignment; (2)~run Scoary on the existing presence/absence matrix + niche labels; (3)~re-BLAST VFDB \emph{setB}; (4)~replace or drop Merz96; (5)~rerun the pan-genome with documented SiLiX-equivalent 80/80 parameters; (6)~add a PHASTER (or PHASTEST) pass on nucleotide assemblies that still need to be fetched.
