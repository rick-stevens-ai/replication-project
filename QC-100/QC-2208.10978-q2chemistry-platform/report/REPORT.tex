\begin{abstract}
We independently exercise the headline sanity-check claim of the
Q$^2$Chemistry platform paper (Fan \emph{et al.}, arXiv:2208.10978):
that a VQE with a UCCSD-family ansatz, driven by a PySCF-generated
molecular Hamiltonian, reproduces the FCI ground-state energy of
H$_2$ along a potential-energy curve. Because the Q$^2$Chemistry
package itself has no publicly installable release (no PyPI, no
obvious public GitHub as of 2026-07-03), the replication uses
open-source functional equivalents (PySCF + OpenFermion) that
implement the identical algorithm (Jordan--Wigner + UCCSD + VQE).
Across 5 bond lengths (0.5--2.0~\AA), the VQE energy matches FCI
to $\leq 10^{-12}$~mHa (i.e.\ floating-point roundoff), twelve
orders of magnitude below chemical accuracy. Verdict:
\textbf{REPLICATED} for C1 (Fig.~6 H$_2$ curve, spot-check scale
at STO-3G / 4~qubits instead of ccj-pVDZ / 40~qubits); the paper's
scale claims (C3 72-qubit Cr$_2$ MPS, C4 EOM-ADAPT-C silicon
bands) and the package's public availability (C5) are
\emph{not} reproduced here.
\end{abstract}

\section{Paper Summary}
Q$^2$Chemistry is a Python/C++ software platform from Zhenyu Li's
group at USTC for quantum-chemistry algorithms on quantum
computers. The paper is primarily a software / platform
description: it explains the modular architecture
(\texttt{q2chem.qchem}, \texttt{q2chem.qcirc}, ansatz builders,
MPS backend, distributed parallelisation via OpenMPI/mpi4py) and
gives two representative numerical demonstrations:
\begin{itemize}
  \item \textbf{Fig.~6 --- H$_2$ potential energy curve} using VQE
        with symmetry-reduced UCCSD, ccj-pVDZ basis (40 qubits, 53
        variational parameters), MPS circuit simulator, BOBYQA
        optimiser. Result: VQE curve tracks the FCI reference
        (PySCF).
  \item \textbf{Fig.~7 --- Silicon quasi-particle band structure}
        using EOM-ADAPT-C, MAD 0.047~eV vs.\ EOM-CCSD.
\end{itemize}

\section{Method}
Because Q$^2$Chemistry has no installable public release (C5), we
replicate the same benchmark structure using open-source functional
equivalents: PySCF (identical to the FCI reference the paper uses)
and OpenFermion (Jordan--Wigner encoding + UCCSD generator). This
is the stand-in explicitly permitted by the QC-100 wave brief.

\paragraph{Stack.} \texttt{pyscf 2.13.1}, \texttt{openfermion
1.7.1}, \texttt{openfermionpyscf}, \texttt{qiskit 2.5.0},
\texttt{qiskit-nature 0.8.0}, Python 3.14.6, macOS 25.3.0
(CherryRd), single CPU thread. See
\texttt{report/evidence/vqe\_h2.py} for the driver script and
\texttt{report/evidence/vqe\_h2.log} for the full run log.

\section{Comparison to the Paper}
\begin{itemize}
  \item Paper Fig.~6: ccj-pVDZ / 40 qubits / 560 cores / BOBYQA;
        curve visually indistinguishable from FCI, no numeric
        residuals reported.
  \item This work: STO-3G / 4 qubits / 1 core / COBYLA+BFGS; curve
        identical to FCI to machine precision at all 5 bond
        lengths.
  \item Method structure identical: Jordan--Wigner encoding of
        PySCF-derived Hamiltonian $\to$ UCCSD singlet ansatz $\to$
        gradient-free VQE $\to$ compare vs.\ PySCF FCI.
  \item Difference: basis (ccj-pVDZ vs.\ STO-3G) and backend
        (Julia MPS on 560 cores vs.\ sparse state-vector on 1
        core). The claim being tested is the same.
\end{itemize}

\section{Verdict}
\textbf{REPLICATED (spot-check scale).} The paper's central
platform sanity-check (C1) is reproduced independently on an open
toolchain with essentially zero residual. The scale claims (C3
72-qubit Cr$_2$, C4 Si bands via EOM-ADAPT-C) and the
availability claim (C5, public installability of Q$^2$Chemistry)
are \emph{not} reproduced --- they require the group's own
software plus HPC resources beyond the QC-100 budget.

\section{Critique --- Honest Limitations}
This section is required by the QC-100 replication standard
(Stevens 2026-07-05, ``genuine critique''). What we \emph{did}
verify vs.\ what we did \emph{not}:

\subsection*{What was actually exercised}
\begin{itemize}
  \item The mathematical/algorithmic content of C1: JW+UCCSD+VQE
        on a PySCF Hamiltonian reproduces PySCF FCI on H$_2$. Yes,
        reproduced to $10^{-12}$~mHa on 5 geometries.
  \item Comparison against a canonical baseline (PySCF FCI): yes,
        this is the same reference the paper uses, so the
        comparison is apples-to-apples for the numerical claim.
\end{itemize}

\subsection*{What was NOT exercised (limits of this
replication)}
\begin{itemize}
  \item \textbf{The Q$^2$Chemistry pipeline itself was not
        independently reimplemented or installed.} The
        replication uses OpenFermion + PySCF as a functional
        equivalent (which is the standard VQE-H$_2$ stack used by
        Peruzzo 2014, Kandala 2017, etc.), not the group's own
        Python/C++ code. Any Q$^2$Chemistry-specific bugs,
        performance quirks, MPS-simulator behaviour, or pipeline
        integration issues would not be caught by this
        replication. In particular the MPS backend (Julia,
        distributed) is entirely bypassed.
  \item \textbf{The specific molecule the paper actually
        benchmarked (H$_2$ in ccj-pVDZ, 40 qubits) was not
        reproduced at the paper's scale.} We used STO-3G / 4
        qubits. STO-3G is a strictly weaker test: for H$_2$ in
        the minimal basis, UCCSD is analytically complete, so a
        machine-precision agreement is the expected \emph{trivial}
        outcome, not a stress test. It does not verify that the
        UCCSD ansatz remains adequate at ccj-pVDZ scale (where
        double excitations into virtual orbitals really matter),
        nor that the paper's symmetry-reduced 53-parameter ansatz
        is chosen correctly.
  \item \textbf{The claimed integration / speedup was not
        quantitatively verified.} We did not measure Q$^2$Chemistry
        wall-clock, MPI scaling, MPS bond-dimension behaviour, or
        the classical-quantum interface latency. C3 (768-core
        Cr$_2$ scaling) is exactly the kind of platform claim
        that only reruns of the group's own code on comparable
        hardware could confirm.
  \item \textbf{C4 (Si EOM-ADAPT-C, MAD 0.047~eV) is untested.}
        EOM-ADAPT-C is a Q$^2$Chemistry-specific implementation;
        no open equivalent was substituted.
  \item \textbf{C5 (public availability) is a negative finding.}
        As of 2026-07-03 we could not locate a pip package or a
        public GitHub repo for Q$^2$Chemistry --- only the group's
        project page. Without the source, the platform claims are
        by construction hard for outsiders to verify at the
        scales the paper demonstrates.
\end{itemize}

\subsection*{Bottom line}
C1 (headline sanity check) is genuinely reproduced. The wider
platform-level story (scaling, integration, performance,
public reusability) is trusted only on the paper's own report and
should not be taken as independently confirmed by this
replication.
