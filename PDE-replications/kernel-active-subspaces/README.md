# Kernel-based Active Subspaces — open replication

**Target paper:** Romor, Tezzele, Lario, Rozza (2020/2022).
*Kernel-based active subspaces with application to computational fluid
dynamics parametric problems using the discontinuous Galerkin method.*
arXiv:[2008.12083](https://arxiv.org/abs/2008.12083) ·
DOI:[10.1002/nme.7099](https://doi.org/10.1002/nme.7099)

**Replicator:** Ollie (OpenClaw subagent), 2026-05-28, on CherryRd.

## What this is

A faithful open-data, open-source replication of the *central claim* of the
paper — that kernel-based active subspaces (KAS) can recover
low-dimensional nonlinear structure that linear active subspaces (AS) miss,
on parametric PDE forward maps. We use the reference implementation
([mathLab/ATHENA](https://github.com/mathLab/ATHENA), MIT) and three
benchmarks:

1. **Radial cosine ridge** (the paper's canonical KAS sanity test) —
   `cos(||x||^2)` on `(-3,3)^2`, where 1-D linear AS provably fails and
   1-D KAS succeeds.
2. **Parametric Poisson on the unit square** with a 5-D Karhunen-Loève
   log-diffusion field — a lightweight stand-in for the paper's
   HopeFOAM/OpenFOAM DG run (substitution disclosed in REPORT.md §3).
3. **Nonlinear QoI on the same Poisson problem** —
   `Q(s) = log(∫|∇u|^2) + 0.5*(s_1^2 + s_3^2)` — deliberately constructed
   so the quadratic term has no 1-D linear AS.

## Headline result

| Experiment | Linear-AS test RMSE | Kernel-AS test RMSE | Factor |
|------------|--------------------:|--------------------:|-------:|
| 1. Radial cosine (1-D ridge)             | 0.697 | **0.320** | **2.18×** |
| 2. Parametric Poisson, mean-u QoI (r=1)  | **0.000085** | 0.0025 | 0.034× |
| 3. Nonlinear QoI on Poisson (r=1)        | 0.159 | **0.137** | 1.16× |

KAS wins where it should (1, 3); linear AS wins where the response is already
nearly affine (2). All three results are consistent with the paper's
narrative when read in the right direction.

## A note on a real bug we found

While replicating, we found that ATHENA's
`utils.CrossValidation.run` builds the training mask as `t_mask = ~v_mask`
(bitwise-not on integer indices), which gives negative indices that wrap
around — so the "train" set is the last few samples of the array, plus
duplicates. This makes `feature_map.tune_pr_matrix` degenerate on the
default code path. We bypass it with a clean held-out tuning loop. See
`REPORT.md §5 (Friction)` for details.
